## 4. 规避建议

1. **本插件用户**：无需任何规避。dsh 0.1.5-rc.3 至 0.2.1-alpha.2（含最新发布）均可直接安装使用；与当前下载量最高的 7 个记忆插件共存无冲突。
2. **需要同时使用其他记忆插件**：可放心与 Top7（hindsight、mnemon、openviking、tiddlywiki、a9i5k4-auto-memory、mneme、prime-memory）共装；注意它们多数具备 shell/network/env 权限且部分默认向外部服务（mem0/supermemory/honcho 等）收发记忆，敏感场景请按最小权限选择。
3. **避免共装组合（生态内冲突，与本插件无关）**：dsh-layered-memory / dsh-memory-vault / dsh-plugin-memory / dsh-prime-memory 四者两两不要同时启用；@max-null/dsh-memory 不与 dsh-file-memory 同启；dsh-file-memory 不与 dsh-handoff-compaction 同启。
4. **遇到 `incompatible with dsh… nothing was installed`**：这是宿主版本门禁在保护数据，不要优先使用 `allow-version --accept-risk`（实测强装旧插件可致宿主 fatal）；应等待插件作者发布适配 0.2.x 的版本。
5. **多 profile / 备份**：注意 dsh-mnemon、@openviking/dsh-memory-plugin、dsh-mneme 的数据不跟随 `DSH_HOME`，迁移环境时需单独处理 `~/.mnemon`、`~/.openviking`、`~/.dsh/memory`。

2. **C1/C2/C3 的 duplicate-id 报错未在 0.2.x 现场复现**：源码与作者注释确认同 id，但在 0.2.0-rc.2 上冲突组合在到达 roster id 检查前已因 C5（API 不兼容）fatal；报错文案来自 dsh-prime-memory 自述。
3. **99 个 GitHub-Release-only 长尾包未做真机安装**：均为下载量 <10 的低活跃包，其分发物未经内容审计；静态 manifest 层不适用（无 npm 包）。
4. **真机仅覆盖 web 平台**：本插件 `dsh.client.platform` 声明为 web，未验证 TUI/桌面端；宿主桌面版未参与本轮测试。
5. **L3 未覆盖真实 LLM 会话中的 prompt 组装**（pulls 计数）：隔离环境无模型凭证；section 注册与 thunk 求值由契约层 + 注册状态断言覆盖。
6. **UI 人工视觉检查未做**：设置页的人工渲染确认不在自动化范围内（本仓库 verify.mjs 以桩 ModuleLoader 覆盖客户端逻辑）。
7. **3 个手工补登 bundle 的共装结果**：启用动作经手工编辑 package.json 完成（网络受限期），形态与官方 add 产物一致但非完整官方命令链路。
